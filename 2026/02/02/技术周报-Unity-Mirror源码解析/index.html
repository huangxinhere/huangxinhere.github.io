技术周报-Unity Mirror源码解析

|浏览量:

概述

一个网络游戏通常由高层的管理器（NetworkManager）协调，低层的传输实现（如 KcpTransport/KcpServer/KcpPeer）负责字节的收发；NetworkServer 和 NetworkClient 分别管理服务器端和客户端的连接、消息路由与游戏对象同步。

  • NetworkManager：最高层入口。负责启动/停止服务器、客户端或“Host”（本机既是服务器又是客户端）、管理场景切换、玩家对象的创建等。
  • NetworkServer：服务器端的连接列表、消息分发、服务器侧的 Spawn/Despawn（生成/销毁）网络对象、接收来自客户端的命令并广播状态。
  • NetworkClient：客户端的连接状态、接收服务器消息、发送玩家输入/命令到服务器。
  • Transport（例如 KcpTransport）：抽象的网络传输层（UDP/TCP/KCP等）。负责把消息封包、发到网络；处理重传、分片、拥塞控制等细节（传输层对上层透明）。
    • KcpServer（在 KcpTransport 内部）：具体负责打开 socket、监听端口、接受新的下层连接，并为每个远端创建一个 KCP 会话。
    • KcpPeer：代表单个连接的会话对象。维护该连接的 KCP 状态（序列号、重传、缓冲区等），负责把收到的字节组装成消息并回传给 Transport/上层，或把上层消息打包并发送到底层 socket。

网络层连接

建立服务器

NetworkManager 调用 NetworkServer.Listen(maxConnections)。

NetworkServer 请求 Transport 启动服务端（例如 KcpTransport.ServerStart()）。

KcpTransport 创建 KcpServer，打开 UDP socket，开始监听指定端口，并在内部准备接收循环（I/O 回调或线程/定时器）。

主机模式 Host

  • NetworkManager.SetupServer()
    • NetworkServer.Listen(maxConnections): 负责高层逻辑（连接表、消息handler注册、Spawn/Uspawn等），并检查和设置一些服务器级别变量，委托下一级“打开端口并开始监听”。
      • KcpTransport.ServerStart()：持有KcpServer和Port示例。
        • KcpServer.Start(port)

接下来重点描述KcpServer的工作。

在KcpServer.Start(port)中，通过CreateServerSocket(config.DualMode, port) ：

创建一个 UDP socket（System.Net.Sockets.Socket / UdpClient 的封装），选择 IPv6/IPv4，若 DualMode = true 则为 IPv6 并设置 socket.DualMode = true 以同时接受 IPv4。

SetSocketOption 设置接收/发送缓冲区大小（RecvBufferSize、SendBufferSize），可能设置 ExclusiveAddressUse 或 ReuseAddress 之类选项。

Bind 到 IPEndPoint.Any:port（把 port 绑定到本地地址）。
不会像 TCP 那样 Listen/Accept；UDP 通过接收（ReceiveFrom）来获取每个 datagram 的源地址并根据源地址映射到对应 KCP 会话。


【KCP连接管理】

KcpServer 保存一个连接字典 connections : Dictionary<int, KcpServerConnection>，每个条目代表一个远端客户端。

当收到来自一个新的远端 endpoint 的 UDP datagram 时：
如果还没有对应会话，KcpServer 会分配一个新的 connectionId，创建新的 KcpPeer/connection 实例并把它加入字典。

触发 OnServerConnectedWithAddress.Invoke(connectionId, prettyAddress)，上层（KcpTransport）会把这个转发到 Mirror 的 OnServerConnected 事件，最终 NetworkServer 会创建 NetworkConnectionToClient 对象并把它加入 connections。


服务器监听

客户端把玩家输入或 RPC 发给 NetworkClient -> 传输层 Transport -> KcpPeer 打包并通过 UDP socket 发送。

服务器端 KcpServer 收到包，通过对应 KcpPeer 解包、重组后，向 NetworkServer 报告收到消息，NetworkServer 分发给相应的游戏逻辑（RPC、同步、命令处理）。

如果服务器需要广播状态，NetworkServer 通过每个连接的 Transport 发包给客户端。

客户端请求

NetworkClient 使用 Transport.ClientConnect(address) 向服务端发送连接请求（UDP 下为首个封包）。

KcpServer 在收到新的远端地址后，为这个地址创建一个新的 KcpPeer（或 KCP 会话），完成握手/会话初始化。

与远端交换必要的握手包（如果 KCP 有自定义握手），建立可靠会话。

一旦建立，NetworkServer 在服务器端为该连接创建内部连接对象（Connection）并把它加入连接列表；同时触发连接回调（例如 OnServerConnect），可能会创建玩家对象（spawn）。

断开链接

主动断开：客户端调用断开或服务器调用断开，对应 KcpPeer 关闭会话、释放资源、NetworkServer/NetworkClient 更新状态、触发断开回调、销毁玩家对象（如果需要）。

非正常断开：超时/网络丢包导致 KCP 会话超时，KcpPeer 声明断线，NetworkServer 清理并通知游戏逻辑。
