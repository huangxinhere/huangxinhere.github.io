负数怎么表示？

32位int类型变量范围_int32的范围_荷戟独彷徨的博客-CSDN博客

计算机中的负数表示，是以补码的形式呈现的。

  • 原码：最高位为符号位，0表示正数，1表示负数；
  • 反码：正数的反码等于本身，负数的反码除符号位外，各位取反；
  • 补码：正数的补码等于本身，负数的补码等于反码+1。

这样方便计算机进行直接运算。

int取值范围计算

int数据类型的取值范围计算，以及int类型在内存中的存储形式_int数据类型范围_RoosPan的博客-CSDN博客【对计算过程详细的解释】

按道理来说，

正数最大值：0111111111…111。是2^31-1。

负数最大值：1111111111…111。也是-2^31-1。

但是零有两种表示方法，0000…000，或者10000…0000，所以取前面那个为0的表示方法，后面那个就作为-2^31，所以负数比正数还要多一个。

只不过负数要在计算机内表示成补码，10000…0000先取反(除符号位)再加一，也就是100000…000（好像溢出丢弃了一位）。

基本运算

  • 按位与：0&0=0，0&1=0，1&1=0 全为0才是0
  • 按位或：0|0=0，0|1=1，1|1=1 全为1才是1
  • 按位异或：0^0=0，0^1=1，1^1=0 相同为0，相异为1；所以任何二进制数与零异或，都会等于其本身，即A^0=A。
  • 按位非：1=0，0=1
  • 有符号右移：>>（若正数，高位补0，负数则高位补1）
  • 有符号左移：<<
  • 无符号右移：>>>（不论正负，高位均补0）

运用场景

按位与计算比取模运算快；哈希表；记录状态值（比如int有32位，每一位都可以记录0，1两个状态值，这样节省空间）；可逆加密……

  • 优势：计算快，节约空间
  • 劣势：不直观

技巧

  • 二进制体现的特点

    • 末尾为1就是奇数，是0则为偶数；
    • 其中偶数n比n/2的二进制多一个0，奇数比前一个偶数多一个1

  • 按位与的特点

    • 只有1&1才为1，其余为0；用来保留1，抹去其它位（如判断奇偶数）
    • n&(n-1)能去掉二进制表示的最后一个“1”；例如21&20=20(3个1)，20&19=16(2个1),16&15=0(1个1)，那么分别得16有1个1，20有2个1,21有3个1
    • n&(-n)则是保留最后一个1。同时为了防止-n溢出（负数比正数多一位，所以最小值取反会溢出）要进行判断处理

  • 按位或的特点-*+

    • 只有0|0才为0，其余为1；或许也是能保留0，

  • 按位异或的特点

    • 一个数和本身异或一次为0；
    • 和0异或结果为本身；
    • 满足交换律与结合律（不严格要求运算顺序）
    • 比对两个位是否相同

  • leetcode808.分汤

不是背包问题是概率问题：每一步状态有先后顺序之分。

类似于爬楼梯：

但不同于爬楼梯：每一步的前后状态转移的概率分布相同，所以递推方向可正向或者反向。

  • 正向递推：从 0 分开始，逐步推到 n，每一步由前面的状态累加过来（原先写法）。
  • 反向递推：从 n 或 k 开始，往前推，每一步由后面的状态均值推过来（滑动窗口优化的写法）。

dp[i] = (dp[i+1] + dp[i+2] + ... + dp[i+maxPts]) / maxPts 是反向递推，含义是：

  • 假设你现在分数为 i，下一步可以抽到 1~maxPts 的分数，分别到达 i+1, i+2, …, i+maxPts。
  • 每种情况概率都是 1/maxPts。
  • 所以，得分为 i 的概率，就是“下一步所有可能分数的概率均值”。

希尔排序【插入】

希尔排序是插入排序的一种更高效的改进版本，它与插入排序的不同之处在于，它会优先比较距离较远的元素。希尔排序又叫缩小增量排序。但希尔排序是非稳定排序算法。

希尔排序是基于插入排序的以下两点性质而提出改进方法的：

  • 插入排序在对几乎已经排好序的数据操作时，效率高，即可以达到线性排序的效率；
  • 但插入排序一般来说是低效的，因为插入排序每次只能将数据移动一位；

希尔排序的基本思想是：先将整个待排序的记录序列分割成为若干子序列分别进行直接插入排序，待整个序列中的记录”基本有序“时，再对全体记录进行依次直接插入排序。

【算法描述】

1.选择一个增量序列t1，t2，…，tk，其中ti>tj，tk=1；
2.按增量序列个数k，对序列进行k 趟排序；
3.每趟排序，根据对应的增量ti，将待排序列分割成若干长度为m 的子序列，分别对各子表进行直接插入排序。仅增量因子为1 时，整个序列作为一个表来处理，表长度即为整个序列的长度。

Leetcode 215

  • Hoare 分区：双指针从两端向中间走，左指针停在 ≥pivot，右指针停在 ≤pivot，若未交叉就交换。最终枢轴所在的“等于区”位于中间，但返回值通常是分界索引（不一定是枢轴原位）。优点：交换次数少，对大量重复值更稳。
  • Lomuto 分区：常见实现是把 pivot 置于末尾，用指针 i 维护 <(=) 区，遍历指针 j 扫描，遇到满足条件就交换到 i 前进，最后把 pivot 换回 i。实现简单，但在大量重复值或有序数据下容易让 pivot 停在边缘，退化更快。
  • 三向跳过（或三向分区）：把数组一次分成 < pivot、== pivot、> pivot 三段。好处是如果有大量等于 pivot 的元素，可以一轮就“跳过”整段等于区，搜索区间大幅收缩，避免退化。
  • TLE（Time Limit Exceeded）：运行时间超过在线评测设定的时间限制，程序被判失败。常见原因包括算法复杂度过高，或在极端数据下退化到最坏情况（如不平衡分区导致 quickselect 变 O(n²)）。

归并排序

对于每个未排序的数组来说，先分成两部分，再分别排序，接着合并。

也就是自顶向下，递归分区，直到分成单位为止，再一一向上合并。

另外是自底向上的方法，从单个元素邻近合并，再扩大合并范围，直到一整个数组。
